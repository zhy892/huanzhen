# 外环识别验证记录

## 范围

本轮仍为确定性图像算法，没有训练分类器或神经网络。用户提供的聊天图片用于观察成像问题；执行环境没有对应图片文件，未将它们记为已运行、已拟合或已训练的数据。

新增夹具用于复现中心暗环缺失、外环被屏幕截断、环心偏离十字线、密集污斑、摩尔纹、RGB 量化和更紧的取景区域。夹具具有独立已知的椭圆几何值，不是用户实拍照片。没有重新引入网站仿真入口。

## TDD 证据

1. **失败基线**：在 `32ebdbd` 的原始 `core/` 快照上运行新增外环测试。5 项中 2 项失败：含密集污斑和纹理的两个正例均返回空结果；3 项对照通过。没有改动生产算法后再宣称该基线失败。
2. **固定验收**：正例须自动输出曲线，中心误差小于 5 个分析图像素，长半轴误差小于 5 像素，轴比误差小于 0.03，绝对级次仍未知。无环的纹理及污斑图必须不输出椭圆。这些断言未因实现困难而放宽。
3. **中途反例**：单纯平滑曾把污斑拼为假椭圆；无环反例捕获该回归。因此增加独立暗带核验，不能只按拟合残差验收。
4. **浏览器失败再现**：颜色转换和屏幕取景区域裁切后，纯算法正例曾在页面返回空结果。先增加两项取景回归测试，再修正尺寸搜索与候选去重，保留不同轴比和方向的搜索种子。
5. **分级失败测试**：先证明“少量分散弧段且有强独立证据”的例子被完全拒绝，再允许其进入“待复核”；弱证据及角度集中反例仍拒绝，定量使用门槛不降低。

执行：

npm run lint
npm test
npx wrangler types .wrangler/runtime.d.ts --config dist/server/wrangler.json --include-env false

基线可将提交 `32ebdbd` 的 `core/` 导出到临时目录，复制当前外环测试与 `tests/fixtures/obscured-screen.mjs` 后直接运行，无需部署或外部服务。

## 方法与限制

- 保留严格拟合，只有宽暗纹的定位波动较大时才使用由纹宽估计、最大 4.5 个分析图像素的筛选容差。
- 细纹理与宽暗纹分开处理，屏幕边框和十字线不作为观测点。使用较强滤波时，接受条件仍由原始分析视图核验。
- 备用暗带搜索具有固定位置、尺寸、轴比和方向范围及候选上限；不保证识别任意构图或任意遮挡。它只提供拟合初值，最终曲线须重新提取暗纹点并通过质量检查。
- 明暗核验比例是有两侧有效采样的位置中满足暗纹条件的比例，不是识别准确率、统计概率或整圈覆盖率。
- “待复核”允许显示模型外推的弧段，同时继续阻止误差归因和补偿。未知级次不被改为第一级；曲率半径仍来自实际输入读数和级次差。
- 阈值是当前工程初值，尚未用独立真实实验集标定。下一步需要以图片文件提供实拍数据，逐张检查叠图、处理耗时与人工复核结果，再以未参与调整的照片检验泛化能力。

## 浏览器回归

独立的页面检查保存在 `tests/browser/outer-rings.mjs`，复用相同夹具生成 PNG，再经过上传、颜色转换、成像区定位和原图精化。它检查最终展示的曲线，而非仅检查内部函数返回值。

先启动本地生产构建，再执行检查（Chromium 路径按环境调整；Playwright 可装在临时目录，不影响站点依赖）：

```sh
npm run build
npm start -- --port 3024
# 在另一终端执行
npm install --prefix /tmp/huanzhen-browser --no-package-lock playwright
PLAYWRIGHT_MODULE=/tmp/huanzhen-browser/node_modules/playwright CHROMIUM_PATH=/usr/bin/chromium node --experimental-strip-types tests/browser/outer-rings.mjs
```

输出叠图和指标保存在系统临时目录下的 `huanzhen-ring-browser/`。当前完整测试为 49 项通过；页面回归中的三个受控正例都满足同样的几何误差要求，均标为待复核。另已检查普通清晰图片、重复复拍续记、曲线更新、多照片打印和原始读数报告。

这不等于用户三张实拍照片已通过，也不能由单次处理耗时推定所有设备的性能。真实照片仍待提供可读取文件后逐张验收。
